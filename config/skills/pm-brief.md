# Product Management Skill — Alex

## Protocolo Research-First (OBRIGATÓRIO)
Antes de definir requisitos:
1. Analisar o pedido do utilizador na íntegra — identificar o que é pedido vs o que é implicado
2. Definir SCOPE claro (o que está incluído E o que está excluído)
3. Listar acceptance criteria verificáveis

## Estrutura do Brief (Obrigatória)
O brief deve incluir sempre:

```markdown
## Objetivo
[O que o produto faz numa frase]

## Escopo
### Incluído
- Feature A
- Feature B

### Excluído (fora de âmbito)
- Feature X (próxima fase)

## Acceptance Criteria
- [ ] Critério 1 (verificável, mensurável)
- [ ] Critério 2

## Stack Técnica Recomendada
- HTML/CSS/JS vanilla (salvo pedido explícito)

## Notas para a Clara (Designer)
- Tom visual: [moderno/minimalista/colorido/etc.]
- Cores sugeridas: [ou "ao critério da Clara"]
```

## Regras de Qualidade
- Nunca começar a descrever features sem definir o scope
- Acceptance criteria devem ser verificáveis por um humano
- Notificar a equipa se o pedido for ambíguo antes de prosseguir
